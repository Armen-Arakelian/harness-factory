# Recall Research Memory

The project root is three directories above this skill folder. Resolve paths from that root and read the relevant Reading and Research and User Conclusions sections of `rules.md`. Recall is read-only, including agent memory, links, and settings.

1. Identify the intent: recall the user's saved position, recover research progress, or assess factual support. Extract subjects, scope and time constraints; translate search terms into English and try useful alternative names. A saved position is not proof.
2. Use the README map and compact Current State for orientation. Search filenames, headings and bounded text matches in `nodes/`, `people/` and `conclusions/`, including unlinked conclusions. When prior ideas or plans matter, search headings and relevant passages of `ideas.md` too; retain their user-selected rating as context, not evidence. Do not preload the whole idea list for unrelated research. Narrow noisy queries before opening many candidates; maps and graph connections are not exhaustive indexes.
3. Read matching short notes and conclusions in full. For a question about the user's view, these may suffice: do not open details merely to restate the saved thought. For evidence assessment, identify the claim and inspect candidate detail headings and approximate length before choosing what to read. A short, wholly relevant detail may be read in full. For longer or mixed-topic details, select the relevant evidence, source and limitation sections; expand only when surrounding context is needed. If tool output is truncated, retrieve narrower sections rather than treating the clipped output as a complete read. Retrieve agent insights or preferences only when relevant.
4. Expand when evidence is missing, ambiguous or conflicting: follow useful links, search detail content directly, and try related terms. Preserve contradictory evidence and useful unlinked records. No fixed file count or graph-hop limit applies. Stop when the question is supported and material conflicts are addressed; never bulk-load the vault, Research Trail or `work/` by default.
5. Report saved wording faithfully, with references to the actual notes; distinguish it from agent hypotheses and factual assessment. Discuss material objections without narrowing or editing the user's thought. For resumption, reconcile the recorded next step with the current request and available artifacts; a checkpoint date cannot prove freshness. Distinguish requested continuation from an agent suggestion and disclose missing context rather than inventing it.

Say "I did not find a matching saved record" when searches fail, not that the user never thought or discussed it. Historical wording may be unavailable: do not reconstruct it from summaries or use Git as a recall dependency. Use this workflow when prior memory matters, not for unrelated replies. A requested memory change uses its preview-and-approval workflow separately; recall grants no write approval or permission to sync state.
